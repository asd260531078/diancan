# 流畅度优化：改了什么、怎么部署

## 必做：重新部署 3 个云函数

在微信开发者工具里，对下面三个目录分别右键 →「上传并部署：云端安装依赖」：

- `cloudfunctions/familyApi`（新增 `getCatalog`、`getDishDetail`、`getMyOpenOrderSummary`）
- `cloudfunctions/notifyOrder`（修正通知跳转路径和 openapi 权限声明）
- `cloudfunctions/uploadImage`（`wx-server-sdk` 统一为 3.0.1）

小程序端对旧云函数做了兼容：没重新部署时会自动退回旧接口，不会白屏，但也拿不到提速效果。

## 建议：数据库索引

云开发控制台 → 数据库 → `orders` 集合 → 索引管理，添加：

| 字段 | 用途 |
|---|---|
| `userOpenId` 升序 + `createdAt` 降序 | 「我的订单」列表 |
| `userOpenId` 升序 + `status` 升序 | 底部角标的未完成订单数 |
| `status` 升序 + `createdAt` 降序 | 厨师端按状态筛选订单 |

`meta` 集合（存菜单版本号）会在第一次修改菜单时自动创建，也可以手动建一个。

## 可选：厨师端实时收单

厨师端会尝试用数据库实时推送监听新订单，有新单立刻提醒；监听不可用时自动退回每 15 秒刷新一次。
要启用实时推送，在 `orders` 集合的「数据权限」里选自定义安全规则：

```json
{
  "read": "get(`database.admins.${auth.openid}`).enabled == true",
  "write": false
}
```

这条规则只允许 `admins` 集合里（文档 ID 为 openid）且 `enabled: true` 的管理员读订单。
不要改成「所有用户可读」。

## 可选：微信订阅消息（小程序没打开时也能收到新订单）

1. 微信公众平台 → 订阅消息 → 选用一个「新订单提醒」类模板，复制模板 ID。
2. 填到两个地方（同一个 ID）：
   - `config/notify.js` 的 `newOrderTemplateId`
   - `cloudfunctions/notifyOrder/template.js`（或在云函数环境变量里设置 `NEW_ORDER_TEMPLATE_ID`）
3. 核对 `cloudfunctions/notifyOrder/index.js` 里 `data` 的字段名（`phrase1`/`date2`/`amount3`/`item4`）和所选模板一致，不一致就改成模板里的字段名。
4. 重新部署 `notifyOrder`。
5. 厨师在「菜品管理」页点「开启新订单提醒」，授权时勾选「总是保持以上选择」。之后每次在订单详情里改订单状态，都会静默续一次订阅。

微信的一次性订阅是“同意一次，发一条”，所以需要第 5 步的续订。

## 这次改动一览

| 位置 | 之前 | 之后 |
|---|---|---|
| 菜单接口 | 每次返回全部菜品的完整做法（食材、步骤、旧版文字做法） | 只返回摘要；版本号没变时只回一句“没变化”；云函数实例内复用结果 |
| 首页首屏 | 1000 道菜时首屏 setData 约 1.6MB（每道菜在“全部”和所属分类各一份，还带做法） | 约 12KB：每个分类先渲染 20 道，滚到底再追加 |
| 本地快照 | 单个存储 key，菜多时会超过 1MB 上限而写入失败 | 分块存储，并去掉空字段 |
| 搜索 | 每输入一个字就改写所有分类面板 | 输入停顿 120ms 后在全部菜品里搜，结果单独列表、分页显示 |
| 详情页 | 打开一道菜拉 1~2 次整张菜单，加菜时再拉一次 | 用菜单里的摘要立刻出画面，做法单独查这一道菜；加菜不联网 |
| 加菜反馈 | 每次弹“已加入”Toast 挡住操作 | 轻震 + 购物车角标弹一下 |
| 购物车 | 每次操作同步读写存储并重新迁移 | 内存里保存，存储改为异步写 |
| 底部角标 | 每次显示页面都翻遍全部历史订单 | 一次按状态查询；多个页面并发时合并为一个请求，5 秒内复用 |
| 常点推荐 | 读本机旧缓存，实际一直是空的 | 用云端最近 30 单统计，首页新增「最近常点」 |
| 下单 | 提交后等 0.5 秒再跳转；详情页再读一次订单 | 立即跳转，直接显示刚提交的订单 |
| 管理端 | 每次进入整页显示“连接中”并重载；切换开关后整表重载 | 静默刷新；开关只更新这一行；菜多时可搜索并分页 |
| 图片上传 | 原图转 base64 上传，多张图逐张串行 | 压到 1080px 宽后上传，多张图 2 路并发（顾客浏览菜单时图片也更小） |
| 分包 | 第一次点进详情或下单要等分包下载 | 在首页预下载 `package-extra` 和 `package-order` |
| 编辑菜品 | 从全量列表里找这道菜 | 单独读完整数据（列表只有摘要，不这样改会在保存时丢掉做法） |

## 测试调整

原来的 `wood-theme` 和 `phase4-order-wood-icons` 两个测试对木纹写法的要求互相矛盾，当前主题里也已经没有木纹设置，属于过时的样式文本检查。已删除其中木纹、旧图标名和旧安全区数值的断言，其余检查保留并改名：

- `tests/theme-layout.test.js`：主题色、卡片布局、饮品弹层、导航栏颜色
- `tests/order-display-title.test.js`：订单标题生成、新旧订单列表显示

视觉效果以开发者工具和真机预览为准。
